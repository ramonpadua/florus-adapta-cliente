# AP-2026-10-26-1555 — Ação que exige campo deve abrir o campo junto ao botão

**Contexto:** T-F2-008 (rollback transversal) — o painel de motivo do Rollback/Rejeitar ficava fixo no FIM da seção Trilha. O champion clicava o botão e nada parecia acontecer ("o botão não executa nenhuma ação"); na verdade o sistema esperava o motivo obrigatório no painel distante. Duas rodadas de confusão (25/10 e 26/10) antes do aceite.

**Padrão:** quando uma ação exige um campo obrigatório, o campo deve abrir NA PRÓPRIA LINHA/posição do botão clicado (autoFocus, fundo destacado, Confirmar/Cancelar inline) — não num painel fixo distante da ação. Painel distante = ação "morta" para o usuário, mesmo com o fluxo correto no servidor.

**Correção aplicada (v0.0.164):** Fragment com 2ª `<tr>` colSpan=7 dentro do map da trilha (linha + linha de motivo), painel fixo removido. Provado na tela com rollback real.

**Regra derivada:** em emendas de usabilidade, testar a DESCOBERTA da ação (o usuário encontra o próximo passo sem instruções?), não só a execução técnica. O TDD via API não pega esse tipo de problema — só o teste humano revela.

**Secundário (mesma task):** rota server-side custom no frontend deve usar `pb.baseUrl`, nunca caminho relativo (o fetch relativo cai no servidor estático do preview e o catch engolia o erro — tela vazia sem pista). Erro de fetch nunca pode ser engolido em silêncio.
